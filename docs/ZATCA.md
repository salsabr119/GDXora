# الفوترة الإلكترونية (ZATCA / فاتورة)

## ما تم تنفيذه — المرحلة الأولى (الإصدار) + أساس المرحلة الثانية

| المتطلب | التنفيذ |
|---|---|
| فاتورة ضريبية (B2B) / مبسطة (B2C) | `invoices.invoice_kind` → `0100000` / `0200000` |
| فاتورة / إشعار دائن / إشعار مدين | `doc_type` → 388 / 381 / 383. الإشعار يلزم أن يشير إلى الفاتورة الأصلية ويذكر السبب |
| منع التعديل والحذف بعد الإصدار | محفّزات (triggers) + صلاحيات على مستوى العمود. التصحيح بإشعار فقط |
| بيانات المشتري في الفاتورة الضريبية | `issue_invoice` يرفض الإصدار إذا غاب الرقم الضريبي للمنشأة أو العنوان الوطني الكامل |
| UUID لكل فاتورة | `zatca_uuid` |
| عداد الفواتير ICV (متسلسل بلا فجوات لكل شركة) | `zatca_state.last_icv`، يُقفل (row lock) عند الإصدار |
| بصمة الفاتورة السابقة PIH | القيمة الأولى المعيارية `NWZlY2Vi…` ثم بصمة آخر فاتورة. لا تُصدر فاتورة جديدة قبل حفظ بصمة السابقة |
| ملف UBL 2.1 XML | `src/lib/zatca/ubl.js`: البائع، المشتري، البنود، الخصومات، ملخص الضريبة حسب الفئة (S/Z/E/O مع رموز الإعفاء VATEX)، استرداد الدفعة المقدمة كخصم على مستوى المستند، والمحتجزات كملاحظة |
| بصمة الفاتورة | SHA-256 على نص XML بصيغته القانونية (canonical)، بعد حذف `UBLExtensions` و `Signature` ومرجع الـ QR |
| رمز QR | TLV → Base64 بالحقول 1 إلى 5، وأطوال الحقول تُحسب بالبايت (UTF-8). **مُختبَر مقابل مثال الهيئة المرجعي** |
| الإقرار الضريبي | الدالة `vat_return()` وشاشة الإقرار |

## قيود معروفة — تُنجز قبل التشغيل الفعلي

1. **التحقق الرسمي:** يجب فحص ملفات XML الناتجة بأداة ZATCA SDK (`fatoora -validate`) وبـ Compliance API قبل التسجيل. الـ XML يُنتج مباشرة بصيغة قريبة من C14N، لكنه لم يمر بعد على الأداة الرسمية.
2. **التوقيع الرقمي XAdES** وحقول QR من 6 إلى 9 (البصمة، التوقيع، المفتاح العام، توقيع الشهادة) لم تُنفَّذ بعد. هي جزء من المرحلة الثانية.
3. تقريب الضريبة: الضريبة تُحسب لكل بند ثم تُجمع، وأي فرق تقريب يُضاف إلى أكبر فئة ضريبية. هذا يحتاج مراجعة مقابل قاعدة BR-CO-17 عند الفحص الرسمي.

## خطة المرحلة الثانية (الربط والتكامل)

1. **التسجيل (Onboarding):** لكل شركة ولكل وحدة إصدار (EGS):
   - يولّد الخادم مفتاحاً خاصاً من نوع EC secp256k1 وطلب شهادة (CSR) بالحقول التي تشترطها الهيئة.
   - يُطلب رمز OTP من بوابة فاتورة، ثم تُستخرج شهادة الامتثال (Compliance CSID).
   - تُجتاز فحوصات الامتثال، ثم تُستخرج شهادة الإنتاج (Production CSID).
2. **حفظ الأسرار:** يُحفظ المفتاح الخاص في Supabase Vault أو خدمة KMS، ولا يُحفظ أبداً في جدول عادي ولا يصل إلى المتصفح. أما `zatca_state.csid_certificate` فيحفظ الشهادة العامة فقط.
3. **التوقيع:** دالة خادم باسم `api/zatca/sign` تضيف توقيع XAdES-BES داخل `ext:UBLExtensions`، وتضيف حقول QR من 6 إلى 9.
4. **الإرسال:**
   - الفاتورة المبسطة تُرسل عبر Reporting API خلال 24 ساعة، ويمكن تشغيل ذلك من طابور `outbox`.
   - الفاتورة الضريبية تُرسل عبر Clearance API **قبل** مشاركتها مع العميل.
   - نتيجة الإرسال تُحفظ عبر `zatca_set_status()` في الحقلين `zatca_status` و `zatca_response`.
5. **البيئات:** `zatca_state.environment` يأخذ إحدى القيم sandbox أو simulation أو production.

> الهيئة تُلزم المنشآت بالمرحلة الثانية على موجات حسب حجم الإيرادات. تحقّق من موعد موجتك في بوابة فاتورة.
